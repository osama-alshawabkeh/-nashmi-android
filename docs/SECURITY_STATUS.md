# حالة الأمان — Nashmi v1

## الحالة الحالية
هذا Proof of Concept فقط.
- اتصال التحكم وبيانات النفق يستخدم TCP خاماً.
- لا توجد TLS certificate validation أو certificate pinning.
- يستخدم Token مشتركاً بين العملاء.
- لا توجد حسابات منفصلة أو إلغاء اعتماد جهاز فردي.
- لا توجد حدود معدل أو سجلات تدقيق أمنية مكتملة.
- لا توجد اختبارات ضغط أو اختبارات اختراق.

## ممنوع حالياً
- لا تفتح TCP 7000 أو 7001 أو منافذ الخدمات للعامة قبل معالجة الأمان.
- لا تمرر كلمات مرور أو بيانات مرضى أو معلومات مالية أو بيانات شخصية.
- لا تعتبر Token وحده حماية كافية على شبكة عامة.

## متطلبات ما قبل النشر
1. TLS 1.2+ على قنوات التحكم والبيانات مع تحقق من شهادة الخادم.
2. هوية ومفتاح مستقل لكل جهاز، وإمكانية إبطال الجهاز.
3. تدوير الرموز وحفظ الأسرار في Android Keystore.
4. تحديد المنافذ المسموحة لكل جهاز وعزل جلساته.
5. حماية HTTP/HTTPS المنشورة، وحدود اتصالات ومعدل طلبات.
6. اختبارات reconnect، انقطاع Wi-Fi/4G، reboot، sleep، وقياس الذاكرة والحرارة.
7. مراجعة قيود Foreground Service في Android 16 وسياسات Google Play.

Unlimited لا تعني قدرة غير محدودة؛ السعة الفعلية تعتمد على الاتصالات المتزامنة وthroughput وRAM والمعالج والحرارة ورفع الإنترنت.
